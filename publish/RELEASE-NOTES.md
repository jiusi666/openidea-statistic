# Statistic 代码统计 0.2.1

修掉 `0.2.0` 里的一个 P2：**缩进语言（Python / Ruby 等）文件末尾的最后一个函数不会被记录**。

`0.2.0` 引入「最长函数」这一项时，缩进语言的循环只在遇到 dedent 行时记录函数。如果一个函数一直开到文件末尾、后面没有任何 dedent 行，它就被完全丢掉：单函数文件直接报「没有函数」，多函数文件会错误地报前一个函数。连带把风险分、项目树徽标和「只看高风险」筛选一起带偏。

## 修复

- 循环结束后按**最后一行有效代码**给还开着的函数收尾，长度口径与 dedent 分支完全一致（尾随空行与注释行不计入）。
- 回归验证 reviewer 举的场景：「811 行函数 + 15 个简单 if」在文件末尾，修复前风险分 **26**（低于 45 的高风险阈值，徽标和筛选都拿不到），修复后 **51**，与后面多跟一句无关顶层语句时同分。
- 新增 4 项用例：单函数到 EOF（无 / 有尾随换行、尾随空行与注释）、最长函数位于文件末尾、EOF 与 dedent 情形长度和风险分一致、阈值场景精确等于 51。单测 29 → **33 项**。

## 0.2.0 的功能（本版一并提供）

从「数行数」变成「找该重构的文件」：按语言 / 目录 / 文件三种维度统计行数，并给出圈复杂度、最大嵌套深度、最长函数（含起始行）、TODO 密度与 0–100 风险分；高风险文件在项目树上带 `!!` / `!` 徽标，悬停看详情，点面板里的行直接跳到最长函数。

## 口径说明

复杂度是**文本级近似**，不建语法树：分支按关键字计数，嵌套按括号深度（缩进语言按 4 空格折算），函数长度靠「函数头 + 缩进 / 大括号配对」识别，字符串与行尾注释先剔除。适合一眼看出哪个文件不对劲，不替代 SonarQube 一类完整静态分析；文档、配置、JSON 不参与复杂度计算。

- 市场：`Settings › Plugins › Available` 搜索「Statistic」。
- 从包：`Settings › Plugins › Install from Disk` 选 `jiusi.statistic-0.2.1.oiplugin`。
- 装完确认四件事：版本号是 `0.2.1`；「按文件」能看到风险分与指标；项目树高风险文件有感叹号徽标；能力弹窗只问 `project.read` + `storage`。
