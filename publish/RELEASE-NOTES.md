# Statistic 代码统计 0.2.0

从「数行数」变成「找该重构的文件」。这一版把面板从**行数统计**升级成**代码健康度视图**，能力与隐私承诺完全不变：仍然只有 `project.read` + `storage` 两个 Low，不联网、不执行程序、不写项目文件。

## 新增

- **按文件分组**：每个文件给出总行、代码行、圈复杂度、最长函数（行数 + 起始行）、最大嵌套深度、TODO 数与 0–100 风险分；默认按风险分排序，可勾选「只看高风险」。
- **风险分**：按复杂度、超长函数、超长文件、深嵌套、TODO 密度加权；阈值（800 行 / 60 行 / CC 15）都能在设置里改。
- **项目树标注**：高风险文件在项目树上带徽标——≥70 分红色 `!!`，≥45 分黄色 `!`，悬停看到「1,284 行 · 圈复杂度 42 · 最长函数 96 行 @L88 · 嵌套 5 · TODO 3」。默认开启，可在设置里关掉。
- **点击跳转**：点面板里的文件行，直接跳到该文件最长函数的起始行。
- **概览卡**换成文件数、总行、代码行、高风险文件数、注释率、TODO 数；空行与体积移到页脚。

## 改进

- 分组表从 8 列压到 6 列，380 px 窄侧栏不再横向滚动；空行与体积放到行悬停提示里。
- 文件列表改成两行式布局：完整路径 + 风险分一行，指标一行，长路径不再被截成 `src/main/java/...`。
- 缓存键升到 v2，升级后自动重扫一次，不会用旧结构的结果渲染。
- 单测 19 → 28 项，`clippy -D warnings` 零告警；包 137 KB。

## 口径说明

复杂度是**文本级近似**，不建语法树：分支按关键字计数、嵌套按括号深度（缩进语言按 4 空格折算）、函数长度靠「函数头 + 大括号配对」识别，字符串与行尾注释先剔除。它适合一眼看出哪个文件不对劲，不替代 SonarQube 一类完整静态分析；文档、配置、JSON 不参与复杂度计算。

## 安装与验收

- 市场：`Settings › Plugins › Available` 搜索「Statistic」。
- 从包：`Settings › Plugins › Install from Disk` 选 `jiusi.statistic-0.2.0.oiplugin`。
- 装完确认三件事：版本号是 `0.2.0`；切到「按文件」能看到风险分与指标；能力弹窗只问 `project.read` + `storage`。
